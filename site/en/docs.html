What pilo ispilo가 무엇인가

Three coding agents open is three conversations cut in half. You remember which window knows about the checkout code, you paste the same context into the second one, and by the afternoon the answer you wanted is in a pane you have already scrolled past.코딩 에이전트를 셋 띄우면 대화도 셋으로 끊겨요. 어느 창이 결제 코드를 아는지 외우고, 같은 맥락을 두 번째 창에 다시 붙여 넣고, 오후가 되면 원하던 답은 이미 지나쳐 스크롤한 어딘가에 있어요.

pilo puts one desk in front of them. You talk to the desk; it decides whose work a request is, hands it on, and writes back one answer. pilo starts no agents and speaks to no provider — it finds the panes you already opened and wakes them.pilo는 그 앞에 창구를 하나 둬요. 말을 거는 상대는 창구 하나고, 그쪽이 누구 일인지 정해 넘기고 돌아온 걸 모아 한 번에 답해요. pilo는 에이전트를 띄우지 않고 제공자와 직접 말하지도 않아요. 이미 열어둔 창을 찾아 깨울 뿐이에요.

The screens in this document are the real app against a demo desk — three projects that do not exist and requests that never happened.이 문서의 화면은 실제 앱이고, 데이터는 시연용이에요. 있지도 않은 프로젝트 셋과 일어난 적 없는 요청들입니다.

Three kinds of agent에이전트는 세 종류예요

The split exists so that no one has to hold everything. The desk holds the conversation, an owner holds a project, a specialist holds one area of it.아무도 전부를 들고 있지 않게 하려고 나눈 거예요. 대화는 대표가, 프로젝트는 담당이, 그 안의 한 분야는 분야 담당이 들어요.

Desk · pilo The only one you talk to. Reads the request, decides whose work it is, gathers what comes back and writes one answer.말을 거는 상대는 이 하나예요. 요청을 읽고 누구 일인지 정하고, 돌아온 걸 모아 한 번에 답해요.
Owner · pm One project, one owner. Reads only its own folder, does the work, reports to the desk.프로젝트 하나에 담당 하나예요. 자기 폴더만 보고 일한 뒤 대표에게 보고해요.
Specialist · worker Sits under an owner and covers one area — review, QA, a second runtime. Reports to its owner, never to you.담당 아래에서 한 분야만 맡아요 — 검수·QA·다른 런타임. 담당에게 보고하고, 사용자에게 직접 말하지 않아요.

Underneath, pilo finds the panes with herdr, wakes one, and the agent answers by running pilo commands of its own. Everything crosses a unix socket on your machine.안쪽에서는 herdr 로 창을 찾고 깨우면, 에이전트가 자기 쪽 pilo 명령으로 답을 보내요. 오가는 건 전부 내 컴퓨터의 유닉스 소켓을 지납니다.

three things share the machine — your terminal, herdr, and pilo한 기계 안에 셋이 같이 있어요 — 내 터미널, herdr, 그리고 pilo

Install설치

Nothing is compiled and nothing asks for sudo. pilo is a terminal tool, not an app bundle, so there is no security prompt to clear.컴파일도 sudo도 없어요. pilo는 앱 번들이 아니라 터미널 도구라 열어야 할 보안 창도 없어요.

TERMINAL
$ curl -fsSL https://pilo.garamnoh.workers.dev/install.sh | sh

It clones the source into ~/.pilo/app, installs the two dependencies and links pilo into ~/.local/bin.소스를 ~/.pilo/app 에 받고 의존성 두 개를 설치한 뒤 pilo 를 ~/.local/bin 에 연결해요.

Node.js 20+ runs the server, the terminal UI and the CLI서버·터미널 UI·CLI 를 돌려요
herdr the terminal workspace pilo watches — brew install herdrpilo 가 지켜보는 터미널 작업 공간 — brew install herdr
one coding agent코딩 에이전트 하나 Claude Code or Codex, opened by you in a herdr paneherdr 창에 직접 띄운 Claude Code 나 Codex

To remove it: rm -rf ~/.pilo/app ~/.local/bin/pilo — your requests and their history stay in ~/.pilo until you remove that too.지울 때: rm -rf ~/.pilo/app ~/.local/bin/pilo — 요청과 기록은 ~/.pilo 를 지우기 전까지 남아요.

First run첫 실행

The first run creates the database under ~/.pilo/data, enables pgvector and applies the migrations. There is nothing to install first and no password to keep: the database is a directory only your account can read.첫 실행에서 ~/.pilo/data 에 데이터베이스를 만들고 pgvector 를 켜고 마이그레이션을 적용해요. 먼저 깔 것도, 보관할 비밀번호도 없어요. 내 계정만 읽을 수 있는 폴더입니다.

When a provider’s window runs out제공자 한도가 찼을 때

pilo parks that runtime until it reopens, and hands the parked agent’s unopened queue to its owner. Work does not sit in a dead pane waiting for a window that is closed.그 런타임을 세워 두고, 열리지 않은 대기열은 담당에게 넘겨요. 닫힌 창을 바라보며 일이 멈춰 있지 않게요.

A limit also arrives as a note, so you find out without going to look.한도가 찬 것도 알림으로 와요. 찾아보지 않아도 알게 됩니다.

the runtime waits; the work does not런타임은 기다리고, 일은 기다리지 않아요

Everything it keeps is under ~/.pilo보관하는 건 전부 ~/.pilo 안에

The database is PGlite — PostgreSQL 18 compiled to WebAssembly, opened as a directory of files, with pgvector enabled. There is no container and no separate server.데이터베이스는 PGlite 예요 — PostgreSQL 18 을 WebAssembly 로 컴파일한 것이고 폴더째 열립니다. 컨테이너도, 따로 띄우는 서버도 없어요.

~/.pilo/config.toml settings설정
~/.pilo/data/ the database itself데이터베이스
~/.pilo/logs/ logs로그
~/.pilo/port the port the server settled on서버가 잡은 포트
~/.pilo/db.lock written while the database is open. A second server refuses to start rather than corrupt the files — PGlite has no lock of its own.데이터베이스를 연 동안 쓰여요. 두 번째 서버는 파일을 망가뜨리는 대신 시작을 거부합니다. PGlite 에는 자체 잠금이 없어요.
127.0.0.1 the only socket that listens, for the dashboard. No account, no telemetry, no outbound connection.듣는 소켓은 이것 하나, 대시보드용이에요. 계정도 수집도 바깥 연결도 없습니다.

Commands명령

The ones you use:쓰게 되는 것들:

TERMINAL
$ pilo # the terminal UI $ pilo dashboard # the browser desk $ pilo inbox [id] # requests, or one request in full $ pilo agents # id · name · role · project $ pilo history # what was asked, answered and reported before $ pilo schedules # standing work $ pilo doctor # diagnostics

Agents have their own set — pilo task, pilo progress, pilo done, pilo block, pilo reply — written into their instruction file when you register them. pilo help lists every one.에이전트용은 따로 있어요 — pilo task·progress·done·block·reply. 등록할 때 지시 파일에 적힙니다. 전체 목록은 pilo help.

Inside the terminal UI, :help does the same. :dash, :project <name>, :follow, :fold, :cost and :icons are the ones worth knowing.터미널 UI 안에서는 :help 가 같은 역할을 해요. :dash · :project <이름> · :follow · :fold · :cost · :icons 정도는 알아 둘 만합니다.

Running a second instance두 번째 인스턴스 돌리기

Every part of the layout moves, which is how a test instance runs beside a real one.경로가 전부 움직여서, 시험용을 실제 것 옆에 나란히 돌릴 수 있어요.

PILO_HOME where config, logs and the lock live설정·로그·잠금이 있는 자리
PILO_DATA the database directory데이터베이스 폴더
PILO_PORT the port to listen on들을 포트
PILO_SOCKET the unix socket the CLI talks toCLI 가 붙는 유닉스 소켓
PILO_SPOOL the file spool used when the socket is unavailable소켓을 못 쓸 때 쓰는 파일 스풀
PILO_WATCHER=off start without the loop that wakes agents에이전트를 깨우는 루프 없이 시작

Move the socket and the spool together — the CLI falls back from one to the other, so changing only one leaves it talking to the instance you meant to leave alone.소켓과 스풀은 같이 옮겨야 해요. CLI 가 둘 사이를 오가며 대체하기 때문에, 하나만 바꾸면 건드리지 않으려던 인스턴스에 말을 걸게 됩니다.

every path moves, so the two never meet경로가 전부 움직여서 둘이 만나지 않아요

When something is off막힐 때

pilo doctor says what is missing. The rest is usually one of these.pilo doctor 가 무엇이 빠졌는지 알려줘요. 나머지는 대개 아래 중 하나예요.

The tree shows boxes나무에 네모가 보여요 the terminal font has no glyph for that runtime. :icons off switches to letters and keeps the answer; PILO_ICONS=off does it for a whole shell. No terminal can be asked whether its font carries a glyph.터미널 글꼴에 그 런타임 글리프가 없어서예요. :icons off 로 글자로 바꾸면 다음 실행에도 남고, PILO_ICONS=off 는 셸 전체에 적용돼요. 글꼴이 글리프를 가졌는지 터미널에 물어볼 방법은 없어요.
Columns drift열이 어긋나요 PILO_AMBIGUOUS_WIDTH forces the East Asian ambiguous width when the startup probe cannot run.시작할 때 폭을 재는 검사가 안 되면 PILO_AMBIGUOUS_WIDTH 로 동아시아 문자 폭을 지정해요.
It refuses to start시작을 거부해요 another server still holds ~/.pilo/db.lock. Close that one first.다른 서버가 아직 ~/.pilo/db.lock 을 잡고 있어요. 그쪽을 먼저 닫아요.
An agent never answers에이전트가 답을 안 해요 its session is gone. The Agents tab says so, and the work goes back to its owner.세션이 끊긴 거예요. 에이전트 탭에 그렇게 표시되고, 일은 담당에게 돌아갑니다.
