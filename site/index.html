ONE PLACE TO TALK

You stop moving between tabs탭을 옮겨 다니지 않아요

Three agents open is three conversations cut in half. pilo puts one desk in front of them and gives each project an owner.에이전트를 셋 띄우면 대화도 셋으로 끊겨요. pilo는 그 앞에 창구를 하나 두고, 프로젝트마다 담당을 정해요.

Desk agent대표 The only one you talk to. It reads the request, decides whose work it is, and writes back one answer.말을 거는 상대는 이 하나예요. 요청을 읽고 누가 할 일인지 정한 다음, 돌아온 걸 모아 한 번에 답해요.
Owner담당 One project, one owner. It reads only its own folder and reports back.프로젝트 하나에 담당 하나예요. 자기 폴더만 보고 일한 뒤 대표에게 보고해요.
Specialist분야 담당 Sits under an owner and covers one area. The name is the area.담당 아래에서 한 분야만 맡아요. 이름이 곧 담당 분야예요.

in the app: the desk, its owners, their specialists앱 화면: 대표·담당·분야 담당

THE TRAIL

You can see how far a request got요청이 어디까지 갔는지 남아요

Five stages are kept, from what you said to the answer that came back. The terminal shows the last one; the rest is there when you want it.말한 내용부터 돌아온 답까지 다섯 단계가 남아요. 터미널에는 마지막 답만 보이고, 나머지는 필요할 때 열어보면 돼요.

You do not repeat yourself다시 설명하지 않아요 What you asked yesterday is on record.어제 무엇을 시켰는지 기록에 남아 있어요.
You see who did what누가 했는지 보여요 Each request keeps which owner did which part.요청마다 어느 담당이 무엇을 했는지 같이 남아요.
A failure is a record too실패도 기록이에요 A request that never landed because a session was down stays visible, and goes again once it is back.세션이 꺼져 전달되지 못한 것도 그대로 남고, 세션을 켜면 다시 보내요.

LOCAL ONLY

The record stays on your machine기록은 내 컴퓨터에 있어요

pilo passes what you said to sessions that are already signed in. There is no API key to paste, and no conversation leaves your Mac. Only an update check and a daily line of usage counts go out, and both can be switched off.pilo는 이미 켜져 있는 세션에 말을 전달해요. API 키를 넣지 않고, 대화 내용은 밖으로 나가지 않아요. 밖으로 나가는 건 업데이트 확인과 하루 한 번 사용 횟수뿐이고, 둘 다 끌 수 있어요.

No API keyAPI 키가 없어요 The agents are already signed in. pilo only speaks to their windows.에이전트는 이미 로그인된 채로 켜져 있어요. pilo는 그 창에 말만 전달해요.
Your files stay as they are내 파일은 그대로예요 It writes one marked block in each agent's AGENTS.md or CLAUDE.md, and nothing else.각 에이전트의 AGENTS.md나 CLAUDE.md에 표시된 블록 하나만 써요. 다른 파일은 그대로 둬요.
Removing it leaves the work지워도 일한 건 남아요 Delete pilo and the documents and repositories are still there.pilo를 지워도 문서와 저장소는 그대로 남아요.

WHERE PILO SITS

pilo is the deskpilo는 창구예요

pilo app TERMINALS Where the agents' terminals live. A background daemon keeps them, so closing the window or updating leaves every session running.에이전트 터미널이 사는 곳이에요. 백그라운드 데몬이 붙잡고 있어서 창을 닫거나 업데이트해도 세션은 계속 돌아요.
Claude Code · Codex AGENT The ones reading and changing code, each in its own folder.코드를 읽고 고치는 쪽이에요. 각자 자기 폴더에서 일해요.
pilo AGENT DESK Where you speak. It does not replace the agents; it decides where a request goes and gathers what comes back.내가 말을 거는 곳이에요. 에이전트를 대신하지 않고, 어디로 보낼지 정하고 돌아온 걸 모아 답해요.
INSTALL

One line and it is installed한 줄이면 설치돼요

One Mac app and one small server, both in Rust. Nothing asks for sudo and nothing else needs installing first. You need Claude Code or Codex, signed in once; the app checks on its first screen. The build is not notarised yet, so run it from a terminal.맥 앱 하나와 작은 서버 하나, 둘 다 Rust 예요. sudo 도, 미리 깔아둘 것도 없어요. Claude Code 나 Codex 에 한 번 로그인만 해두면 돼요. 앱이 첫 화면에서 확인해요. 아직 공증 전이라 터미널에서 실행해요.

FAQ

Asked often자주 묻는 것

Does pilo start the agents?에이전트를 pilo가 만드나요? No. You register sessions that are already open. The app can also open a new session for you with one button.아니에요. 이미 켜둔 세션을 등록해서 써요. 앱에서 버튼 하나로 새 세션을 열 수도 있어요.
Where does my data go?제 데이터는 어디로 가나요? Nowhere. It sits in a SQLite file, ~/.pilo/pilo.sqlite, on your own Mac. Once a day pilo sends usage counts (a random install id, version, macOS, chip, how many agents per runtime and how many requests, tasks, results, approvals, window choices, schedule runs and wakes), never content, prompts, paths, names or accounts, and no IP is kept. Turn it off on the first screen, in Settings, or with PILO_TELEMETRY=off.밖으로 나가지 않아요. 내 Mac 의 SQLite 파일 ~/.pilo/pilo.sqlite 에 저장돼요. 하루 한 번 사용 횟수(무작위 설치 id, 버전, macOS, 칩, 런타임별 에이전트 수, 요청·작업·결과·승인·창 선택·예약 실행·깨우기 횟수)만 보내고, 내용·프롬프트·경로·이름·계정은 보내지 않으며 IP 도 남기지 않아요. 첫 화면, 설정, PILO_TELEMETRY=off 로 끌 수 있어요.
Do I need an API key?API 키가 필요한가요? No. pilo speaks to agent sessions that are already signed in.필요하지 않아요. pilo는 이미 로그인된 세션에 말을 전달할 뿐이에요.
Do I need tmux or another multiplexer?tmux 같은 멀티플렉서가 필요한가요? No. The agents' terminals live in the pilo app, kept by a background daemon, so closing the window or updating keeps the sessions running.필요 없어요. 에이전트 터미널은 pilo 앱 안에 있고 백그라운드 데몬이 붙잡고 있어서, 창을 닫거나 업데이트해도 세션은 계속 돌아요.
Does it change files in my repository?제 저장소 파일을 고치나요? One marked block in AGENTS.md or CLAUDE.md. Nothing else is touched.AGENTS.md나 CLAUDE.md에 표시된 블록 하나만 써요. 다른 파일은 그대로 둬요.
Can I answer approvals from a phone?폰에서 승인할 수 있나요? No. Phone pairing and the browser dashboard are gone in 0.4.0; the Mac app is pilo's only face. Every approval, Pilo's own hooks included, can be answered there, risky ones are marked in red, and each answer from the app is logged (the rule and the tool, never the command).아니요. 0.4.0 에서 폰 연결과 브라우저 대시보드는 빠졌고, 이제 Mac 앱이 pilo 의 유일한 화면이에요. Pilo 자체 훅까지 모든 승인을 앱에서 답할 수 있고, 위험한 건 빨간색으로 표시되며, 앱에서 한 답은 기록돼요(규칙과 도구만, 명령은 남기지 않아요).
