GETTING STARTED

Getting started시작하기

Installed to a first answer, in seven steps.설치부터 첫 답까지, 일곱 단계예요.

Installed to a first answer. Each step says which screen you are on before it says what to type, and ends with what you should see. Numbered steps are the ones everybody walks; anything below a dashed line is only for when something is wrong.설치부터 첫 답까지예요. 단계마다 지금 어느 화면인지가 먼저 나오고, 그다음이 거기서 칠 것, 마지막이 무엇이 보이면 넘어가도 되는지예요. 번호가 붙은 것은 모두가 순서대로 밟는 것이고, 점선 아래는 안 될 때만 보는 곳이에요.

three screens — your terminal, the desk that replaces it, and the same desk in a browser화면은 셋이에요 — 터미널, 그걸 덮는 데스크, 브라우저의 같은 데스크

01terminal터미널Install설치
TERMINAL
$ curl -fsSL https://pilo.garamnoh.workers.dev/install.sh | sh
Clones the source into ~/.pilo/app and links pilo into ~/.local/bin. Nothing is compiled and nothing asks for sudo.소스를 ~/.pilo/app 에 받고 pilo 를 ~/.local/bin 에 연결해요. 컴파일도 sudo 도 없어요.
you are through when되면
pilo --help prints the command list. You are still in the shell.pilo --help 가 명령 목록을 뱉어요. 화면은 아직 터미널 그대로.
if it says command not found안 되면 — command not found
~/.local/bin is not on your PATH. The installer prints the line to add.~/.local/bin 이 PATH 에 없는 거예요. 설치 스크립트가 넣을 줄을 그대로 알려줘요.
TERMINAL
$ export PATH="$HOME/.local/bin:$PATH"
02terminal → setup터미널 → 설정 화면Run it — the setup screen comes first실행 — 설정 화면이 먼저 떠요
TERMINAL
$ pilo
The desk does not open yet. With no desk agent registered, pilo shows a setup screen instead, and it stays there until you make one. Shell commands do not work here — commands inside the desk start with a colon.데스크가 바로 열리지 않아요. 대화할 데스크 에이전트가 아직 없어서 설정 화면이 대신 뜨고, 만들기 전까지 여기서 안 넘어가요. 셸 명령은 여기서 안 먹어요 — 데스크 안의 명령은 콜론으로 시작해요.
THE SETUP SCREEN
● setup required ✓ herdr running ✓ Database ready ○ desk agent registered (role=pilo) ○ PM agents (optional)
The first run creates the database under ~/.pilo/data, enables pgvector and applies the migrations, so the first two usually pass on their own. The third is what you are about to do.첫 실행이 ~/.pilo/data 에 데이터베이스를 만들고 pgvector 를 켜고 마이그레이션을 적용하니, 위 두 줄은 대개 알아서 켜져 있어요. 세 번째가 이제 할 일이에요.
you are through when되면
The setup screen appears with the first two checks passing.설정 화면이 뜨고 herdr running 과 Database ready 에 체크가 있어요.
if nothing appears, or herdr shows zero안 되면 — 화면이 안 뜨거나 herdr 가 0 일 때
The desk is holding this terminal, so open a second tab to look. This is not a step everybody takes.데스크가 이 터미널을 쓰고 있으니 탭을 하나 더 열어서 봐요. 모두가 밟는 단계가 아니에요.
TERMINAL
$ pilo doctor # what is missing $ pilo status # what is running
With herdr not running there is nothing for an agent to attach to. Start herdr first.herdr 가 안 켜져 있으면 에이전트가 붙을 자리가 없어요. herdr 부터 띄우세요.
03a second terminal tab터미널 탭 하나 더Make the desk agent — once, ever데스크 에이전트 만들기 — 딱 한 번
The desk cannot be made from the dashboard and is not created for you. This is the way.데스크는 대시보드로 못 만들고 저절로 생기지도 않아요. 아래가 유효한 경로예요.
TERMINAL
$ pilo up # server only, if it is not up already $ herdr agent list # find the folder of the session you want $ pilo api POST /api/agents '{ "name": "pilo", "role": "pilo", "runtime": "claude", "cwd": "that session’s folder", "writeRules": true }'
cwd binds the herdr session for you, and writeRules writes the instruction block into that folder's CLAUDE.md or AGENTS.md.cwd 로 herdr 세션이 자동으로 연결되고, writeRules 가 그 폴더의 CLAUDE.md 나 AGENTS.md 에 지침 블록까지 써 줘요.
you are through when되면
The check on the setup screen passes and that screen turns into the desk.설정 화면의 desk agent registered 에 체크가 들어오고, 그 자리가 데스크 화면으로 바뀌어요.
409 means it already exists409 가 오면 이미 있는 거예요
Only one agent may hold role=pilo. A 409 means there is nothing to make.role=pilo 는 하나만 둘 수 있어요. 409 는 만들 필요가 없다는 뜻이에요.
04the desk데스크Open the dashboard대시보드 열기
INSIDE THE DESK
:dash
Typed inside the desk. The same desk opens in a browser on 127.0.0.1 — whichever you type in, the other shows it.데스크 안에서 치는 명령이에요. 브라우저에 127.0.0.1 주소로 같은 데스크가 열려요. 어느 쪽에 써도 다른 쪽에 보여요.
you are through when되면
The browser opens with the rail on the left — work, agents, requests, schedules, and the rest.브라우저가 열리고 왼쪽에 레일이 보여요 — work · agents · requests · schedules 등.
to open it without leaving the desk데스크를 안 나가고 열려면
pilo dashboard in another terminal tab opens the same page.다른 터미널 탭에서 pilo dashboard 를 쳐도 같은 화면이 열려요.

06dashboard대시보드Register the owner agent담당 에이전트 등록
agents → Add agent, with the role set to PM. pilo lists the herdr panes it can see; pick the one that owns this project. The desk was made in 03 and cannot be made here.agents → Add agent, 역할은 PM. pilo 가 herdr 판 목록을 보여주면 이 프로젝트를 맡을 판을 고르면 돼요. 데스크는 03 에서 만들었고 여기서는 못 만들어요.
It writes the instruction block into that folder's CLAUDE.md or AGENTS.md; the agent reads it on its next turn.고르고 나면 그 폴더의 CLAUDE.md 나 AGENTS.md 에 지시 블록을 써 넣어요. 에이전트는 다음 차례에 그걸 읽어요.
you are through when되면
The agent shows as pm, and the block is in that folder's CLAUDE.md.agents 목록에 pm 으로 뜨고, 그 폴더의 CLAUDE.md 안에 블록이 들어가 있어요.
if no pane is offered고를 판이 하나도 없으면
Nothing is running in a herdr pane yet. Open one, start Claude Code or Codex in it, and refresh this screen.herdr 판에 코딩 에이전트를 안 띄운 거예요. 판을 열고 Claude Code 나 Codex 를 실행한 뒤 새로 고치면 올라와요.
07the desk, either one데스크 — 어느 쪽이든Say one thing, get one answer요청 한 건 넣고 답 받기
Type it at the prompt. You do not name an agent: the desk reads the request, decides whose work it is, and hands it on. While it is out, the line under your request says who is holding it; when everything lands you get one answer, in the language you asked in.프롬프트에 그냥 적어요. 누구에게 시킬지 안 고릅니다 — 데스크가 읽고 누구 일인지 정해서 넘겨요. 일이 나가 있는 동안 요청 아래 줄에 누가 들고 있는지가 붙고, 다 들어오면 답이 하나로 와요. 물어본 언어로.
you are through when되면
One request, one answer — and requests keeps every stage it went through.요청 한 줄에 답 한 줄. requests 화면에 그 요청이 거쳐 간 단계가 남아 있어요.

The screens here are the real app against a demo desk — projects that do not exist and requests that never happened.이 문서의 화면은 실제 앱이고 데이터는 시연용이에요. 있지도 않은 프로젝트와 일어난 적 없는 요청입니다.
